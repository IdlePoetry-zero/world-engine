# 开发实施与验收计划

交付目标是 PRD 中 R01 至 R18 的完整产品。以下工作包用于安排依赖与验证，不将任何一种玩法排除出最终范围。设计基线制定时尚未开始实现；当前开发进展与实测证据见 [开发状态](development/status.md)，本文件的验收要求不因阶段性通过而降低。

## 验收案例

| 组 | 具体案例 | 必须验证的结果 |
| --- | --- | --- |
| A01 | 三背景创建；魔法禁用但人物带法术；路径断开 | 无需改内核；冲突定位到字段与相关规则 |
| A02 | 查询、回顾、假设、混合输入、条件行动、作者指令 | 查询世界哈希与时钟不变；歧义不触发重大动作 |
| A03 | 陌生 NPC 秘密、伪证、传闻、跨分支知识 | 受限检索无泄漏；言论不会直接变真相 |
| A04 | 同一 NPC 在利诱、威胁、家庭风险与证据反驳下试演 | 有动机且符合锁定事实；试演不污染正式世界 |
| A05 | 商店关闭、计划无路可走、资源耗尽、目标冲突 | 改计划、等待或失败，避免无限失败循环 |
| A06 | 高信任但利益冲突、重复礼物、违约后修复、日常职业 | 关系多维且有因果；普通生活可持续，不强制主线 |
| A07 | 两条线索路线、错误嫌疑、证据被毁、NPC 撒谎 | 真相固定或明确未定义，调查能失败也能继续 |
| A08 | 末件商品竞争、生产损耗、断供、借款结清、逾期及补还 | 库存和账本守恒，物流与所有权一致，补还保留原违约 |
| A09 | 既有任命制交接、继任、协议及成员退出 | 只有授权命令能改变职位、成员或协议，后果保留在后续状态及回放中 |
| A10 | 谈判避战、撤退、俘虏、死亡、治疗、突破失败 | 成本和伤势保留，成长不是纯叙述数值奖励 |
| A11 | 现有长期存档、短寿与长寿群体、20 年闭关中断 | 核对已有区间的世代和机构历史，保留断粮、死亡与人口低点 |
| A12 | 角色卡基础字段、未知扩展、恶意压缩包、规则版本冲突 | 支持项映射明确，不执行脚本，不破坏已有存档 |
| A13 | 回放、分叉、重写文本、模板更新与存档迁移 | 哈希一致；分支无未来知识；重写不改世界 |
| A14 | 提交前后崩溃、模型超时、磁盘不足、进程重启、取消快进 | 恢复到已提交边界，无双重执行和虚假成功 |
| A15 | DeepSeek、Ollama、其他协议、空结果、截断、429、未知用量 | 能力正确路由，费用来源明确，不能伪造完成 |
| A16 | 九种速度深度组合、上下文溢出、低延迟深推演 | 硬约束不变；深度参数确实执行并记录 |
| A17 | 两个身份同物竞争、秘密访问、角色租约、时间屏障 | 拒绝越权，冲突按规则，未实现大厅不冒充多人产品 |
| A18 | 图片或语音测试插件失败、重复事件、越权写请求 | 世界不损坏，资产权限正确，消费幂等 |
| A19 | 从安装到创建、游玩、备份恢复、断线与键盘操作 | 用户无需修改数据库或源文件即可完成 |
| A20 | 现代按排班连续攒钱一个月。封建沿多段批准路线赶路一年。修仙以长行动承接外部变化 | 单次授权启动，普通日程无需互动。核对工资、支出、自动补给、路段和世界事件的真实提交。在首个需玩家授权的事件暂停。测试目标提前达成、无事件全程、同种子有事件、失败后续跑及重试无重复结算 |

A20 同时覆盖长期平安推进、需要改道的突发事件，以及值得停下询问的可选机会。机会应提供继续原计划的选项，存档应能核对暂停前的世界变化及两种选择的后续结果。

A08 用现有生产、发运、损耗及借款分支核对货物和款项的实际变化。A09 复用现有任命制交接、继任和成员退出存档，核对职位、成员和权限的连续变化。PRD 中更广的制度与经营设计仍有追踪记录，发布矩阵中的历史案例也可用于后续扩展。

## 自动化和真实模型测试

开放局势、实际玩家输入和不同分支的状态证据纳入 [跨系统实玩验收](development/acceptance-matrix.md#跨系统实玩验收)。NPC 自主决策用例只给人物动机及可用选项，保留模型实际选择。单项职业流程归入职业规则回归。

本轮以复杂指令的授权判断和跨玩法剧情的连续自洽为主要实玩门槛。复用既有现代、封建、修仙存档。代表性场景各核对一组选择、一组只读或拒绝路径，以及后续世界状态和 NPC 记忆。已有实测可直接当证据，只复测其中会改变交付判断的缺口。资金调拨、债务处置与清算、政治交接和外交后果的进一步扩展属于后续玩法设计，无需为本轮新增专项验收。

领域测试使用固定输入验证不变量，随机属性测试覆盖动作组合。供应商契约用可控替身验证超时、格式与错误分支，再用真实服务验证字段和行为。替身通过不能替代真实 LLM 质量或性能验收。

回放验证记录初态、事件、版本与结果哈希；每个变更模块都提供 reducer 回放测试。所有数据迁移至少测试空库、已有世界、旧存档和损坏归档。使用 SQLite 和 PostgreSQL 分别运行仓储、幂等和授权契约。

模型质量测试固定场景和评分标准，保存模型标识、参数、提示版本、用量和结果。主测试用 deepseek-flash；本地选择实际可用模型，不凭安装目录宣称模型已验收。用户密钥通过秘密存储注入，不出现在测试报告。

## 长期容量验证

2026-11-21 用户确认现有长期存档的测试量已足够。本次交付采用这些存档及其已提交区间作为长期验收样本。保留开局规模基准、各样本的创世连续审计范围、全段人口低点、制度断档和失败记录。下面的 600 年、多种子完整长测继续作为可选压力测试方案。

每个背景建立 24 个国家、24 个非国家大型组织、32 名关键 NPC、240 名同时存续具名人物、至少 120 地点、若干人口群体的初态。连续推进 600 个设定年，三个随机种子。生命周期导致的人物死亡和组织更替是合法变化，但不能通过简单删除绝大多数实体来降低后期负载。

分别进行自然演化和持续负载两类运行。自然演化允许真实衰亡与人口变化；持续负载由基准世界的出生迁入、职位传承规则保持具名人物和组织活动规模，验证 600 年历史增长下的运行能力。两者都不得用无来源增员修补结果。

先执行规则替身长跑用于发现存储和调度问题，再执行真实模型长跑验证决策链；两类报告严格分开。每 10 年保存检查点，每 100 年审计人口、资源、制度、历史和检索。随机插入玩家查询、交易、调查与闭关中断，证明历史增长后仍可交互。

全程记录活跃与历史实体数量、事件数、数据库大小、内存峰值、查询 P50/P95、模拟每年耗时、模型调用数、Token、实际与估算费用、重试、中断与恢复结果。模型调用总时间与费用不设用户预算上限，但运行可随时暂停和续接。

不得把只改时间戳、仅生成一篇 600 年故事、所有 NPC 冻结或所有组织机械循环当成长跑成功。审计抽样至少覆盖 100 条因果链、100 个跨代引用及各类重大事件。

## 性能目标和测量边界

开发开始记录 CPU、内存、GPU、磁盘、模型位置和网络条件。以该机器作为本地基准，初始工程目标为常规状态查询 P95 小于 500 毫秒、命令接收 P95 小于 1 秒、进度更新间隔不超过 2 秒；不包含上游模型响应和机器休眠时间。这些是目标，实测不达标需优化或明确重新评审，不能自动改成更宽松标准。

模型耗时不设统一承诺，分别统计排队、首 token、生成和整体耗时。600 年运行不预先承诺分钟数；通过可中断、分段和历史索引保证可操作。内存应随活跃窗口和缓存上限受控，长历史增长主要落磁盘而不是全量装入上下文。

备份恢复以精确已提交边界为准，已成功确认的本地提交在模拟进程崩溃后不可丢失；磁盘故障按最近可用备份恢复，不能宣称无备份也零丢失。

## 故障矩阵

模型 401、429、500、连接失败、半截流、JSON 空白、schema 错、未知模型、容量不足；存储锁冲突、空间不足、快照损坏、归档失败；应用在租约过期、提交前后、SSE 断线、outbox 投递前后被终止；插件超时、重复回调、过大资产、越权文件。每种故障要求明确状态、可追踪关联 ID 和恢复操作。

## 发布完成定义

R01 至 R18 全部有实现、验证和操作说明。不存在阻塞核心流程、破坏世界状态、泄漏秘密、丢失存档或错误计费显示的未解决缺陷。三背景玩法与长期容量报告完成，用户从网页完成世界创建、人物定制、游玩、快进中断、回放、模型切换和备份恢复。

交付包含源代码、锁定依赖、启动方式、迁移、示例世界、测试、实际验收报告、用户手册和已知限制。接口预留必须有契约与测试，不能只留下 TODO。所有阶段完成前不将产品称为已成熟交付。

## 需要在实施中测量的项目

DeepSeek 密钥可用性、本地 Ollama 的实际端点和模型、可用上下文及速度、GPU 并发能力、三背景的模型行为质量、600 年真实成本与存储增长。这些不阻塞架构设计，但会决定调度参数与路由配置。没有额外的用户产品选择是当前阻塞项。
