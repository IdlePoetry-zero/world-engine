# 玩法与模拟实现的集成约束

本文件细化设计基线的模块边界，供后续编码交付使用，不代表相应玩法已经完成。

## 已实现的背景包目录

`backend/world_engine/content/ContentCatalog` 已实现 `PackCatalog` 的两个入口：`list_packs()` 与 `build_world(pack_id, title, player_name, *, seed=None, population_mode="natural")`。目录提供三个全容量开局：`low_magic_feudal`（低魔封建）、`modern_city`（现代城市）和 `long_life_cultivation`（长生修行）。当前内容版本为 1.7.0；此版本显式以秒为 tick，并为每位开局具名人物关联一个区域人口组。人口总数满足“未具名人口池 + 当前具名在世成员”。每个区域的人口池还带有年龄分布、逐年龄出生与死亡率，以及精确守时的年度人口事件；年度重复上限固定为 600 次。`population_mode="natural"` 按原有年龄人口规则自然变化；显式选择 `"sustained"` 时，每个区域只为非玩家具名居民启用有限座位补充策略。每个区域还配置了有总额上限的月度食水采收，按角色的真实持有人账户及库存批次发放，并由注册事件记账。所有开局人物持有首月食水存量。旧版 1.0.0–1.6.0 存档保持原样，不会静默迁移。每个包包含独立的政治、经济、人口与场景钩子数据；现代包明确没有超自然能力。

每次建档从 tick 0 开始，生成 12 个区域、107 个普通定居点和 1 个隐藏历史地点（总计 120 个地点）、24 个 polity（国家/政治体）、24 个其他组织、32 个有独立身份与目标的关键人物、240 个有唯一姓名的其他在世人物，以及玩家角色。另有 12 个区域人口组。关键人物档案由内容数据提供；240 位居民从名称池中去重，并按所在地区、职业、需求、技能、人格、资源和目标进行种子化。每个背景都有独立撰写的隐藏地点与历史线索。线索可从玩家开局场景以 history focus 搜索；成功观察只向发现者解锁 3,600 秒短途路线和地点知识，其他人物不会继承其发现。

开局状态同时包含组织成员、领导与章程，组织财政账户，角色持有的资源批次，定居点市场报价及其真实持有人库存账户，定居点生产配方，人物关系、目标和持有者自己的知识记录。每项资源有明确的消耗 sink 和 genesis issuance 账本账户；每个生产场所的输出另有以场所为 owner 的有限 source quota，额度由该配方已分配的有限输入库存推导。区域资源先记为有限库存，再从对应区域账户分配到人物或生产场所，月度食水额度另受每项采收政策的 600 年总上限约束。重要引用在构建时交给 `WorldState` 与组件 schema 验证。人物秘密只作为其持有者的私有 belief 记录；玩家投影保留玩家自己的知识，并过滤作者元数据及其他角色的私有记录。固定输入会产生稳定 UUID；`build_world(..., seed=None)` 沿用自然模式稳定开局，显式 signed-64 位种子会写入 `metadata.generation_seed`，并可重现地改变 NPC 身份组合、地区内安置、年龄和初始需求，同时保持玩家开局位置及各区域具名人口数。`sustained` 模式与自然模式使用不同的世界 identity；给定相同显式种子，NPC 的语义特征保持一致，便于对照长期补充规则。

世界日历固定为 86,400 秒/日；人物年龄、成熟期与寿命使用 `year_days × day_seconds` 换算。现代城市的路线和制作时长以小时配置，另外两个背景的常规路线和制作以日配置；跨背景的一小时隐藏地点短途路线直接写成 3,600 秒。时间单位回归测试验证这些值不会把“年”或“日”误当作秒数。

这里交付的是内容包定义的初始快照，不会预填历史事件，也不把未发生的旅行、生产、政治决定或长期人口变化伪装成已模拟事实。开局预置有限年度人口推进与月度食水采收日程；它们只有在规则和模拟模块执行并记录后才会影响世界状态。内容合同测试位于 `tests/content/test_catalog.py`。

## 所有权与依赖方向

`domain` 定义可验证事实、事件及纯归约；`rules` 计算行动的合法结果；`simulation` 调度自治过程与长期演化；`application` 协调权限、模型、事务与任务；`api` 只做协议适配。内容包只引用注册规则，不执行任意 Python 或 JavaScript。

模型输出只能提出语义意图、候选决策和有来源的叙事。不能把任意 JSON Patch 作为世界事件执行。规则调用应返回规范化事件与裁定依据，由应用层取得当前版本并提交；提交冲突后重新读取和裁定，不把旧事件直接套到新版本。

## 内容目录

公共接口为 `list_packs() -> list[dict]` 与 `build_world(pack_id, title, player_name) -> NewWorld`，已经由 `WorldApplication` 消费。三个完整背景包为修仙、架空历史、近未来科幻。包内明确世界硬规则、角色属性、能力条件、经济资源、日历、寿命、信息渠道、组织制度和合法动作。使用稳定包版本；每次新建世界生成独立实体标识，所有引用一致重映射。

容量配置与小型教学开局分开：验收用 24 国家、24 其他组织、32 关键人物、240 存续具名人物及 120 地点。不能用重复名称、同质空壳 NPC 或不可达地点达到数量。不同人物具备身份、关系、义务、需求、目标、知识与生命阶段；不同组织有资产、成员、领导与制度。实体生成应可由种子重现，并通过引用、控制权、账本和可达性校验。

## 可扩展但有类型约束的事件

现有四种 core 事件只承担基础事务验收。玩法接入前需要扩展明确的生命、能力、关系、知识、目标、组织和生产事件；每种事件具有版本、前置条件、归约和可见性策略。每种组件都由注册 schema 验证，拒绝未知组件写入。作者编辑是独立授权命令，保留来源与版本，不能冒充玩家行动。

资源消费与生产必须具备可审计的来源、去向、转换比例与原因。不能简单修改余额或让购买只扣钱不转移物品。物品唯一性、运输在途、债务期限和组织资产应能关联到权利主体。

## 规则服务契约

动作请求包含动作类型、行动者、目标、参数、时间意图、约束和停止条件。规则注册表提供 schema、可用性检查和纯解析函数；解析返回事件批次、已用时间、随机样本、规则版本、解释引用与中断原因。随机流由世界种子、分支、命令和规则标识派生，不使用进程全局随机状态。

每类玩法必须实现跨系统后果：

- 关系日常：倾听、承诺、帮助、冲突、义务、关系维度和记忆；对方可以拒绝，关系不能一次说服无上限增加。
- 探索调查：移动与耗时、感知条件、线索保管、证词可信度、推断与事实分离；未发现事实不进入玩家上下文。
- 经营生存：需求、库存、交易、制作、运输、生产、价格反馈与破产；市场与货主不共享无限库存。
- 势力政治：成员、权限、财政、命令、条约、合法性、继承、冲突与组织分裂；口头命令不自动控制不服从的组织。
- 战斗成长：距离与资源、回合或时间边界、命中伤害、防御、伤病、死亡、经验与突破条件；失败仍有合法后果。

选举或议会制的主动交权按提名、投票、结算三步处理。在任者发起提名，玩家控制的成员独立投票，NPC 的票应由受约束的角色决策产生。选民名单在提案时固定。选举名单取有效成员，议会名单取持有明确投票授权的成员。规则按已提交票数及章程门槛决定能否结算。通过时在结算提交里更新领导职务。投票期间发生治理变动，须先取消过时提案。公告和玩家界面只显示经投影授权的信息。验收要从同一提名分叉，核对通过及未通过时的领导、成员和后续行动。

跨势力通行协定由两地各自有代表权的领导处理。发起势力提出包含明确路线、方向和期限的条款，接收势力独立批准或拒绝。批准时核对双方当前治理版本。生效后，在该路线出发时给发起势力成员提供约定的通行许可。角色仍须满足交通方式、目的地访问及其他限制。条款到期或任一有权限的缔约方撤销时，后续通行重新按常规规则裁定。验收比较同一提案批准与拒绝分支上的实际移动，并检查非成员、反向路线、到期和撤销。

## 长期调度契约

时间推进由可恢复任务执行，每批次记录起止 tick、采用规则、守恒账、关键事件、下一边界和中断原因。一个成功批次原子保存事件、世界版本和任务进度；租约 fencing token 阻止失效 worker 提交。取消保留此前已提交事实，绝不伪装成整个任务从未发生。

调度边界包括需求阈值、资源耗尽、信息到达、承诺期限、年龄/寿命、成长、生产运输和组织决定。远方地区可聚合，但人物不能冻结，死亡后必须处理继承与未完成义务。具有实际影响的重大人物/政治决定通过模型网关取得合法候选；模型不可用时暂停并说明原因，除非用户明确配置规则代理。

600 年验收需要证明经济流动、人物世代、组织变迁、消息延迟与停止条件实际运行。运行清单同时报告实时存续数量和历史累计数量；历史人物不能计入当前 240 人基线。保存定期检查点和抽样回放哈希，不能仅用终点文字或时钟变化作为证据。

## 会话与模型调用

GM 查询和假设保存在会话记录，不调用世界提交或推进时钟。显式“询问 GM”优先于文本分类；自动模式不确定时返回澄清而不执行。混合输入要分段处理，不能把问句中的行动当成授权执行。

角色对白要先裁定承诺、消息、报价等语义事件，再生成最终措辞；叙事失败不能回滚已成功提交的世界事实，也不能重新执行行动。可重新生成措辞，引用同一已提交结果。查询可直接流式展示；行动叙事只有通过验证后才标记最终。

按需构建不同模型上下文：玩家 GM 解释使用玩家投影，NPC 决策使用该人物知识与记忆，规则裁定只提供所需内部事实。作者模式独立标记。全局状态不能直接塞进所有提示词。

## 验证顺序

先在真实 SQLite 上验证规则事件与回放，再验证单个玩法完整命令，随后检查跨模块后果、真实模型语义、故障恢复、三背景行为与长周期容量。替身响应适用于供应商协议故障注入，不用于声称真实玩法质量。需求矩阵中的每项最终链接测试或人工验收证据。

## 修炼成长与闭关

已学技能训练继续使用世界时间和技能经验。突破尝试需要已登记的功法能力、当前境界符合登记规则、技能达到门槛，并持有可用且来源明确的灵气批次。规则登记给出耗时、消耗、成功条件和失败后果。模型把玩家的选择转成规定的行动，境界、代价和结果由规则确定。

短时尝试按所需时间经过生理和外部事件边界，再以同一命令提交灵气消耗及成败。失败保留代价及已发生的伤势。修为阶段以角色历史里最近一条境界里程碑为准。多年闭关需走持久作业，在每个修炼、断粮、来信、日程和寿命边界上重新结算，并检验中途恢复。年度制度审计与修炼分开记录。此节为实施决策，长闭关联调尚未验收。

## 地方职业传承

具名补员的职业权重改善候选来源，职业训练还需在既有人物身上发生。拟用正式课程、仍在任或仍具资质的导师、学员同意和真实训练时段形成资格记录。没有登记技能的学员可以从零开始登记，合格后再以带来源的事件确认新资格。修订作者设定的旧入口继续用于作者干预。

资格、实际任职、组织入会和领导任命分次决定。持证居民仍需符合章程、年龄、地区和明确入会意愿。导师失能、经费不足或人离开会留下实际的中断。新职业机制以新内容版本和年度处理器注册，可以复核旧存档的原有招募结果。下一步用 Hillview 实玩既有居民学通一项职业，以及没有导师或经费时的对照分支。
