# 世界自治与创作工具开发方案

实施范围以[外部审计采纳记录](deep-analysis-adoption-2026-11-28.md)为准。各项按接口依赖衔接，验收覆盖全部交付。以 `53521ee` 和既有周年账本作为对照。

| 工作项 | 开发方案 | 验收依据 |
| --- | --- | --- |
| 互动后续 | 让议题保留来源、知情者、相关目标与期限。讨论完成后，由角色决定是否调查、商议、行动、拒绝、改期或结束，复用已注册能力。通过证据和规则更新目标、关系或资源。过期、权限变化与重复提交有明确回执。 | 能由行动和结果回查最初的线索，计划和对白本身只证明角色有此意图。 |
| 自治覆盖 | 按角色实际入场、离场和组织存续核对活动窗口，分别记录例行活动、复审、选择、执行与后果。扩大组织自主目标和评估能力，章程、负责人、资源、成员及外部条件决定能做什么，允许暂缓、重组或自然沉寂。 | 给出具名人物、组织及覆盖范围的按期统计，解释没有事件、缺少机会、有机会却没有入口的区别。 |
| 环境与记忆 | 使可配置暗骰可利用当期已存在的供需、天气、人物与机构压力，给模型提供角色可知的近期因果和分层记忆。辨认反复出现的话题、未解决事项和事件实际变化，保留来源及知情范围。 | 同一检查点可以重放。模型提案与裁定有证据，重复互动递减，关键变化使用真实证据。 |
| 游玩界面 | 保留自由文字输入和只读 GM。将已确定参数的面板接入结构化预览、确认和规则提交；按场景呈现操作、日历、地点路线和角色关系。作者可在授权视图读到因果链。原有画面扩展接口继续可用。 | 同一操作的文字路径和结构化路径等价。核对窄屏、知情范围、回执与冲突恢复。 |
| 性能与模块 | 同档测冷读、推进、提交、恢复与重放。验证增量状态校验、序列化复用、周期检查点和保留策略。拆分规则、可见性与仓储热点，按现地能力裁剪模型行动结构，并保留歧义澄清。 | 用对照数据说明收益与代价。旧档哈希、守恒、租约、权限和故障恢复继续通过。 |
| 内容创作 | 提供声明式设定、别名解析、路线与初始化账本核对、角色卡与世界书映射，以及编辑器预览、校验、导出和重导入。区分原作事实、作者配置和存档中发生的事件。 | 两类背景往返导入导出，核对人物、地点、可执行规则、素材权属与来源字段。 |

采用隔离存档在幻想乡和至少一个不同的通用背景走正式 UI/API 与后台作业，覆盖玩家低干预推进和一次合法介入。固定可比较的起始条件，允许角色自主选择及不同结果。验收记录来源、角色知情范围、可行性、实际提交、跨期影响、覆盖缺口、重放、性能和云端用量。检查的是权限、因果和持续性，失败、拒绝、平息和沉寂同样可以有完整证据。正式模型样本使用授权的云端线路，受控回归另记。长跨度根据因果链和对照需要确定，沿用既有容量审计区间。

完整交付包括代码、操作说明、更新日志、脱敏验收报告及复现命令。核对无误后同步原 GitHub 仓库的默认分支并核验远端提交。
