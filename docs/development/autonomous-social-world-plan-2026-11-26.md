# 万象下一轮优化计划

2026-11-26 · 规划基线为 `7d8ca1b`

本轮目标是让玩家在幻想乡待几天或离开一段时间后，能发现 NPC 自己做了什么、彼此关系为何变化、这些变化后来怎样影响选择。同步修复外部审计中影响游玩、存档可靠性和证据复核的问题。引擎能力应可复用于其他世界包。

依据为外部压缩包 `world-engine-audit-20261126.zip`、上轮的[六年验收记录](autonomous-world-followup.md)和[产品需求](../01-PRD.md)。外部审计的严重度作为输入，影响范围和完成条件以本计划中的复核口径为准。

## 一、基线与取舍

六年正式作业覆盖 2,160 个世界日，记录 210 条 NPC 私下交流，其中 181 条为回应，另有 362 次关系维度变化。对一个有大量具名人物的世界，这种有据可查的社交活动偏稀疏。交流记录按事件计算，发起和回复可能属于同一次互动。

六年跑动使用正式引擎、真实存档和受控规划替身。它验证了时钟、状态提交、自治流程和重放，尚待验证真实模型下的角色表现和日常社会密度。外部审计也未做浏览器实玩，其技术发现可用于排修，玩法效果另用短程试玩判断。

## 二、先修会直接卡住玩家的问题

### 第 1 阶段 · 长行动、聊天和可复核证据

1. 在已知请求会写入世界时，调用模型前读取分支是否有活跃作业。明确写入的行动、角色对话和可直接判定的草稿走这一检查。自动模式仍可区分只读问题和写入意图。执行端保留事务内的租约、权限及版本校验。
2. 分支忙时给玩家可读的原因、当前可见的作业进度入口和适用的下一步。只读问答和查看状态可继续使用。对“检查时空闲、提交前被占用”的竞态同样给出可恢复回执。
3. 打通配置读取失败的页内重试，以及发送失败后的原话找回。对于提交状态不明的请求，先核对原回执，确认可重新发送时再编辑。轮询有终态和超时出口，刷新后可找回请求状态。
4. 给精简上下文中的点名实体、已选案卷和证据保留预算。普通在场角色按相关性填剩余空间。重名、有歧义或容量确实不足时向玩家说明，保持原有可见性限制。
5. 提交可随仓库查看的六年摘要，带版本、世界包、介入点、历法、精确边界、事件口径、重放哈希和模型替身声明。提供短程复现命令，将真实模型历史报告和离线模拟报告分别标注。

完成条件是分支忙时明确写入请求可在零额外模型调用的情况下收到反馈，跨状态竞态保护账本，长行动结束后可按原意安全操作。核对只读问答、回复恢复、旧存档分支、模型调用计数和窄屏交互。

关联审计项为 API-03、DOM-04、FE-01 至 FE-03、DEL-01。

### 第 2 阶段 · 模型失败与长作业可靠性

1. 给模型队列和整个请求设置可观测的总期限，排队、执行、重试和回退共用剩余预算。记录排队、实际调用、失败类别和可能计费状态。
2. 对 NPC 的截断和无法解析输出采用可追溯的暂缓或有限重试。已登记计划仍按权限和现实条件执行。引擎保留真正需要玩家授权或规则无法继续时的暂停状态。
3. 区分网关重试、作业恢复和下一次世界内复审。检查重复失败能否在重启后持续打转，避免把偶发停机、作业重领和业务重试混算。
4. 检查分支作业列表及详情的角色可见范围、模型凭据与连接配置的绑定。保留本机 Ollama、兼容云端接口和自定义供应商的正常路径。核验错误日志、导出和审计摘要中的敏感字段处理。
5. 用隔离恢复副本验证原请求标识和回执的关系，明确如何识别已提交的旧命令。容量监督脚本和迁移兼容性单独复验，继续阻止未知版本被意外升级。

完成条件是失败路径能明确说明发生了什么，已有世界状态保持可重放，同一请求或已提交计划不会重复执行。权限用本人、同世界其他玩家、旁观者和作者对照验证。

关联审计项为 API-01、API-04、MOD-01 至 MOD-04、A2-F7、STO-01、STO-05、STO-06。

## 三、让 NPC 平时也在生活

### 第 3 阶段 · 在同一套规则中接入日常互动与重要决定

1. **保留固定日程，加入有原因的偏离。** 住处、营业、值守、习惯和惯常往来产生真实接触机会。临时事务、已有约定、天气、交通、身体状况与关系紧张可以改动当日日程。缺席、拒绝、改期也可以产生后果。
2. **给普通 NPC 通用的互动机制。** 同住、共事、交易、帮助、接待、履约、争执等，只有实际相遇或可达的通信条件成立时才结算。先检视现有日程、能力、记忆和关系事件，复用合法流程。世界包配置接触方式和文化习惯，例如幻想乡的来访与互助、现代背景的同事往来、修行背景的同门合作。
3. **小变化可以积累。** 一次寒暄可能只留下相识，一次帮忙可能微增好感，一次兑现能增进信任。关系保持方向性，变化按下文的曲线、重复行为衰减和关键事件条件结算。
4. **模型进入日常和关键决策。** 模型可按配置批量为有关联的角色提出近期事务，也可在新事件、约定遇阻、发现异常、关系转折时分别给出角色反应。例行规则继续提供日程、接触机会和低风险互动。模型根据性格、已知事实、关系、目标和近期记忆建议行动，正式规则核验并提交。
5. **让玩家回来后看得见世界的变化。** 通过公开场景、本人收到的消息、GM 可说明的事实和经过授权的记录呈现后果。私人谈话保留原有权限。玩家只看场景或问 GM 时，世界保持当前提交时刻。等候、长休息、旅行等实际消耗的时间与外界共用同一条时间线。
6. **保留机构对照。** 红魔馆、守矢一方和至少一个通用背景保留正式目标复审。抽查人手、账本或权限变化会怎样影响行动。报告说明当前验证覆盖的机构和行动类型，机构数量和实际自治覆盖分别记录。

世界基于现实条件自行演化。试玩可以从同一开局分支复用初始条件，但不预设哪位角色必须会见谁、谁一定增进好感或哪条剧情一定发生。

### 区域与群体暗骰

**引擎掷骰，模型构思，引擎裁定。** 每个区域或 NPC 群体有可调整的检查频次、触发概率、冷却期和同时进行的事件额度。用世界日或世界周配置，长休息与普通行动走同一套排程。引擎参照人口、来往、季节、积压事务和近期同类事件确定触发机会。暗骰由存档种子、分支和排程序号绑定，重试同一机会沿用原结果。平静期可以没有新事件。

命中后，模型可根据当地公开及作者授权的状态，创造世界包中未预写的新情况，例如一次临时停船使不同人物的行程产生冲突。它输出起因、参与者候选、地点、持续时间、可见范围，以及可由已有规则承接的后续。引擎按当前存档核对人物是否在场或可联络、权限、资源、时间因果和既有承诺。合规的事件及其依据写入账本，角色仍自行决定参与、拒绝、改期或另找办法。未通过校验的方案可有限修订、推迟或放弃。

模型可提出事故、邀请、流言、新机会或矛盾。流言先作为带来源的说法入账。死亡、资源增减、公开指控和重大世界设定变更等后果需要对应的规则和授权。正常跑动可分别配置三条模型频次，即区域事件生成、NPC 群体近期计划、重要个体反应。频次提升优先增加参与场景和角色覆盖。长跨度可批量提交模型候选，但按真实发生时间逐项校验和落账。记录调用位置、耗时、结果与成本。

首组配置以有人流的区域每天检查一次、偏远区域每世界周检查一次为可调试跑值。检查频次和触发概率独立配置，短测按地区负荷调整。玩家只在角色知道线索时看见后果，世界在其离场期间也可触发。重放使用已记录的掷骰、提案裁定和事件，重新生成仅在新分支或新机会发生。

### 关系及事件影响曲线

好感、信任等有向维度各自结算。新关系默认 0，范围为 −100 至 100。既有存档按原值接入。普通履约优先影响信任，额外帮助、体谅或违背边界的行为按实际情境影响好感。两方可以对同一件事有不同看法。

| 当前分段 | 普通互动 | 关键事件 |
| --- | --- | --- |
| −59 至 59 | 容易变化。同一次行为仍依据后果、期待和人物态度决定增减或为零。 | 可产生较大变化，按实际代价与影响结算。 |
| 绝对值 60–79 | 明显减慢。要求较强或持续的新证据，微小影响可暂存并衰减。 | 信任考验、关系修复或持续冲突等可以产生实质变化。 |
| 绝对值 ≥80 | 保持当前分数，仍可记录共同经历及累积证据。 | 背叛、救助、承担显著代价或在困难中持续修复等，可以推动该维度向任一方向转折。反复忽视也可能形成有证据的累积转折。 |

默认让正负阈值对称，并把关键事件门槛设在**进入 ±80** 时。好感与信任可按人物和世界包配置不同的事件权重。同一对角色、同类原因、相近情境的增益或减益逐步衰减至零。已经预期的例行履约维持关系；成本、风险、影响或承诺对象发生实质变化时才作为新证据。一次事件只能按稳定标识结算一次，换说法或拆成多次请求也沿用原因记录。

在关系临界点、双方对同一事件理解明显不同时，或几件事叠加可能形成转折时，可以请 LLM 判断人物如何解读、主要影响哪个维度、是否具备关键事件的情境。模型须引用角色可知的事实与已提交事件。引擎检查证据、分段阈值、重复性和可用幅度并计算入账值，给回执注明原因。验收覆盖重复履约 100 次、累计伤害、一次真正的背叛，以及关系到高阈值后的修复或恶化。

## 四、长时间推进的性能工作

### 第 4 阶段 · 测量后优化，保留因果与恢复

用同一世界包、存档和推进区间建立前后可对比的性能记录。测量每个世界日的任务、交易和旅程事件量，分别统计 reducer 校验、序列化、数据库写入、历史查询及回放。分清运行时间和排队时间。

优先验证可跳过的空闲区间、例行事件的安全合并、重复序列化与历史索引。后续才评估增量投影或拆分 reducer。出现有人介入、期限到来、资源或权限变化、旅行抵达、玩家决策点等情况时，保留相应边界与账本证据。用既有存档检查兼容、断点恢复、分支隔离和关键轨迹能否重放。

给前端提供可信的已提交进度和最新检查点。自动推进时间长时，玩家能区分“仍在运行”“等待决策”“已暂停”和“失去连接”。以现有的短中程对照测量改进，六年实跑作为历史基准。

关联审计项为 DOM-01、DOM-03、STO-02 至 STO-04、API-05、CI-01。将功能边界与压测假设分别写入报告。

## 五、试玩与交付

| 组别 | 重点观察 |
| --- | --- |
| 六日试跑 | 同一幻想乡开局旁观、离场与局部介入。检查暗骰频次、参与覆盖、互动证据、好感防刷和玩家回访信息，调整频率后再开始正式长跑。 |
| 幻想乡一个完整世界年 · 正式验收 | 按该存档历法实际推进至周年。幻想乡当前为 360 世界日。玩家以低干预游玩和较长离场为主。整年按配置实际使用云端模型处理新事件、群体计划和重要反应，抽查不同季度的成功、拒绝、延后和降级。 |
| 同一起点分支与受控对照 | 固定相同起点和可比较的随机条件，对照离场、局部介入以及关闭事件生成时的差异；对关键变化做分支回放。受控组测规则与恢复，正式全年组保留真实云端参与证据。全程避开本地 LLM。 |
| 另一背景复用 | 检查哪些能力可直接复用，哪些差异由世界包的职业、日程、资源和习惯配置产生。 |

验收报告按月记录提交时钟、触发与搁置的事件、哪些角色发起了互动、关系变化来源、模型参与类别、耗时和费用。按季度抽查原作人物的语气、动机和记忆连续性，追踪至少一条有代表性的跨季后效，同时记下自然沉寂的月份。互动密度结合在场机会和环境解释，允许市集热闹、偏远独居安静。量级用于解释覆盖和节奏，验收以授权、因果、人物自洽、玩家自由和周年重放为准。

本轮交付优化代码、迁移兼容说明、面向玩家的使用说明、更新日志、六日试跑与一年正式验收记录，以及可公开复核的证据摘要。外部报告中剩余观察如通用历史投影、未使用的人口配置、内容版本分支、立绘入口、版本口径、测试辅助代码重复，按实质影响纳入后续工作。现有功能与预留接口在说明中标明各自状态。

## 六、顺序与工期

| 工作段 | 预计工程日 | 依赖 |
| --- | --- | --- |
| 分支忙反馈、输入恢复、点名上下文和证据摘要 | 2–3 | 可直接开始 |
| 模型失败与队列、权限及恢复核查 | 3–5 | 可与第一段部分并行 |

| 长推进测量、低风险优化和短中程对照 | 3–5 | 基线可提前测量；最终对照需纳入新增社交活动 |
| 六日试跑、一年正式验收和交付文档 | 3–5 | 一年实跑的墙钟时间另按试跑吞吐、模型调用量和重放耗时估算 |

并行后先以约 **4–5 个工作周** 作为工程排期估计。六日试跑后再给一年作业的运行时间与调用量预估。若基准显示必须调整存储协议或迁移旧档，在有重复测量和恢复证明后再调整工期。下一轮从第一阶段和日常互动的规则设计开始，优先改善实际游玩中的等待、回访和世界变化。
