# 下一轮游玩修复与优化方案

基线为 `66474dc`，依据 [三方独立评审](three-independent-reviews-2026-11-24.md)。先改善玩家第一次看场景、问人、移动和影响局势的体验，再验证不同背景能否用同一套规则做出不同的选择。

| 优先级 | 改动 | 可验收结果 |
| --- | --- | --- |
| P1 · 抵达与调查 | 为现代开局区分「到达可调查地点」和「查清事故」。从已提交的抵达事实兑现第一步，明确显示下一条可知线索。后续调查沿用证据或案卷规则。核查旧存档、分支、重访和两种旅行入口。 | 种子 4 的直达档与种子 7 的多段档均在实际抵达后显示准确进展。重载和路过重返时结果一致。玩家仅靠抵达不会结案。 |
| P1 · 红雾报告 | 登记时明确选择报告内容和来源，形成可查的规则回执。亲眼观察、他人转述、建议和未经证实的自述具有各自语义。剧情与救济引用实际报告，既有档案里的旧历史保留原含义。 | 用同起点比较只问好、明确无所见、提交未证实说法、提交可查观察和不介入。逐条核对里程碑文案、库存、重复提交和分支重放。 |
| P1 · 首屏与本地 GM | 让场景卡即时显示已知人物、地点和线索。对明确选定的案卷等动作，优先使用带对象标识和幂等键的规则入口。自由问答使用分层上下文和容量受限时的收缩策略，标明请求阶段和恢复选项。 | 全新默认本地配置可观察、建立案卷及追问，观察保持时钟，重复建卷只产生一条案卷。不泄露隐藏资料。记录真实 Ollama 与受控模型两类证据。 |
| P2 · NPC 与 UI | 给 NPC 最近双向对白、玩家可知的实际行程及调整原因。没有证词时也应保持人物语气和保密边界。修正建档摘要，改善手机上看人、发问和返回现场的路径，明确谈话与出发冲突的处理。 | 同刻追问、离场回来、换分支和换人能保持对应记忆。无证词保持未知。窄屏可从场景进入对话。慢请求跨刷新后的处理可核对、可恢复。 |
| P2 · 背景差异与扩展 | 以三个可试玩的短开局验证通用构件。幻想乡用人物态度与异变信息，现代用相互冲突的时间安排和关系，封建用通行、见证与旅程。每个开局至少允许两种有代价差异的介入，以及旁观和自由游玩。 | 用不同意图重复试玩，比较角色、资源、许可或时间线的实际变化。记录作者可复用的位置、角色、证据、承诺和后果接口，以及后续扩展顺序。 |

先完成三个 P1 并在隔离档复验，再合入 NPC、建档和移动体验。用三个背景复核首个可玩循环，补充更新日志与验收记录。新增世界包内容按独立版本构建，兼容旧档与《回灯之约》。后续优先评估作者制作和分支预览工具，以及按玩家行动类别裁剪模型契约的收益。
