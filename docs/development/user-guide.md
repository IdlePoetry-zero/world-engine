# 本地用户操作指南

本指南说明当前网页中已经接通的操作。界面只展示服务端返回的世界状态；没有返回的世界、模型结果或模拟进度不会以演示数据代替。

## 启动

如果项目的 `.runtime\venv313\Scripts\python.exe` 尚未安装，先完成 Python、前端依赖与网页构建。[首次安装](runtime.md#首次安装)

环境已就绪时，在项目根目录打开 PowerShell，运行以下命令。前端构建已有且与源码一致时可直接启动服务。

```powershell
npm --prefix frontend run build
.\.runtime\venv313\Scripts\python.exe -m world_engine.runtime
```

保持运行窗口打开，在浏览器访问 [http://127.0.0.1:8000](http://127.0.0.1:8000)。默认存档目录是仓库的 `.data`。安装环境或排查启动错误可参照[运行时记录](runtime.md)和仓库 [README](../../README.md)。

## 创建与打开世界

1. 打开「世界库」，选择「创建世界」。
2. 选择背景和设定版本，填写世界名称和角色名称。三个背景默认使用 2.0。2.2 提供月度调价与逾期承诺补还，2.3 增加家庭、入职和付薪班次，2.8 增加多段行程中的可选停留。选择「有限补充」后可使用 2.4 或该背景专用的人口配置版本。按需填写随机种子后提交。
3. 等待世界出现在列表中后选择它进入「游玩」。

现代和封建可从建档窗口先选一条开局。例如现代可选「追查末班车」或「约在下一班之前」，封建可选「沿灰境林道出发」或「找桥吏谈修桥摊派」。选开局只会预选对应设定版本，确认后才创建存档。各档都可以自由访人、旅行或继续自己的计划。

幻想乡通过「导入世界包」打开 1.5.0，选红雾介入点。可以在人里查验日影，到神社把现场记录交给灵梦，也可以转述、自述、提出建议或只去拜访。登记界面会说明交出的内容和来源。提交过的报告可在原分支的游玩记录查阅。

三个内置背景均可在「高级设定」选「v2.13.0 · 机构自治与储备策略」。示例国家和组织会根据账本、在任权限与人手决定是否补足日常储备、转向发展储备或暂缓。幻想乡 1.5.0 的红魔馆与守矢一方也遵循这套规则。玩家只浏览或问 GM 时，世界时钟保持原值。选择等候、休息或推进世界可给 NPC 和组织留出实际的世界时间。

创建世界、人物、地点或组织时，可以用 `Tab` 和 `Shift+Tab` 切换窗口内的控件。按 `Escape` 取消并返回打开窗口的按钮。生成预览或提交期间，请等待当前请求返回。作者预览中的「返回修改」会保留草稿，并把焦点移回名称字段。

留空种子时使用设定包的默认生成方式。输入同一版本的设定包、世界名称、角色名称、人口模式、NPC 自主性及种子可复现初始配置。种子支持正负安全整数和 0。「自然演化」允许具名人口随世代变化。「有限补充」会在地区有空席、具备合适的匿名成年人口和有限配给时补充具名居民。版本 1.8 起，使用这一模式新建的世界，各机构每年可依章程录取至多两名符合地域、年龄和职业条件的现有居民。入会后仍须按机构继任规则获得职位。建档后的详情可在「设定档案」查看。

新建世界的 NPC 自主性默认关闭。选择「旅行与采购」时，第 1 个世界日复审一名关键 NPC 的到达目标，第 3、7 个世界日由两名居民各复审一次储备采购目标。「有限自主（旧版 v1）」为最多三名符合条件的居民登记采购复审。推进世界到相应时点后，工作器才调用配置的 NPC 决策模型。角色会按当时的路线、库存、价格和行动权限决定可做什么。模型不可用时，作业可能停在待决定节点。

2.4 的有限补充档有 264 名开局具名居民，另有玩家和 32 名关键 NPC。新增居民在各地区正常生活、消耗配给并经历生命周期。采收前仍可能出现空席，补员受地区成年人口和配给约束。

现代城市的持续人口模式可选 2.5、2.6、2.7 和 2.10。地区职业和技能配置决定开局居民与后续具名补员的职业分布。2.7 中，如果本地缺少章程所需的职业，有配给支持的空席补员会优先考虑相关职业。选择「v2.10.0 · 地区组织招募」时，补员也会检查当地组织能否招到符合年龄、职业和地区要求的非成员，并在有补员席位时优先补充欠缺的职业。入会由组织按章程审核，任职仍遵循继任流程。已有世界按存档的内容版本继续演化。

低魔封建的新世界在持续人口模式下可选 2.9。该版本为地方组织指定驻地，并让各地区从本地职业配置选出开局居民和后续具名补员。加入组织仍需满足章程并经过招募。2.8 的途中机会也可在 2.9 使用。

修仙新世界选择「有限补充」后，可选「v2.11.0 · 地区职业与招募候选」。12 个地区的职业配置用于有空席时补充具名居民，补员时会考虑当地组织缺少的合资格候选人。组织按原章程审批入会。该版本也包含 2.8 的途中机会。

已有有限补充席位的世界也可由作者调整：在「设定档案」选地区人口群体的「人口」组件，登记相应职业的权重，再勾选「优先补充本地机构所需职业」。预览后确认提交。设置只影响以后出现空席时的职业选择，实际入会仍要经过年度招募。地区人数、年龄结构、晋升记录和现任人员在本次修订中保持原值。

## 连接模型与设置速度、深度

打开「模型与运行」后配置模型连接和任务路由。

1. 在「模型连接」中添加供应商，填写连接名称、协议、服务地址和可选的默认模型。Ollama 本地服务的默认地址是 `http://127.0.0.1:11434`；使用云端或兼容服务时，按供应商提供的信息填写地址。
2. 保存连接后，在连接卡片中选择「发现模型目录」。这只读取供应商返回的模型目录，不代表已经验证模型生成能力。
3. 对需要密钥的供应商，在连接窗口的「API 密钥」区域输入密钥并保存。网页会在保存后清空输入框，密钥由 Windows 凭据管理器保存，之后只显示是否已配置。凭据管理器不可用时，密钥输入会停用，不会改存到浏览器或普通文件。Ollama 等本地服务可留空。
4. 在「职责路由」中为各项任务选择首选供应商和模型。选择「使用系统默认」或「自动发现」时，实际使用项以服务器配置为准。兼容协议支持填写手动模型 ID。
5. 如需配置备用，先保存首选模型，再选择「添加备用模型」。每项任务最多配置三个，可用「上移」「下移」调整尝试顺序。各模型可分别保存输出上限。开启「仅使用本地服务」时，云端目标会在发送请求前被过滤。切换前后的调用可在「调用记录」中分别查看。

生成类职责还可以填写「输出 Token 上限」。留空使用引擎为该请求设定的值。模型回复被截断时，可提高相应职责的上限，或缩短当前输入，再重新提交。调用记录会同时列出请求的输出上限与供应商报告的用量。具体模型的输出和上下文额度仍由供应商决定。

切换协议时，地址和默认模型会留在该协议的草稿里。切回即可继续编辑，保存连接后才会应用。已有凭据的连接只允许保留原协议和服务来源。需要连接另一台服务时可以另建供应商。要在原连接改用其他地址，可先显式删除其 Windows 凭据。地址或协议有待保存的修改时，先保存连接再输入新密钥。

Ollama 连接可设置「上下文容量（Token）」。留空时使用本地服务的默认值。引擎把设定值发送给该连接的每次原生聊天请求，职责路由中的输出上限仍单独生效。较大的上下文容量会增加内存占用。遗址场景的实测中，Qwen3 8B 在本机使用 16,384 Token 后可以完成此前被上下文限制拒绝的查询。 [Ollama 上下文说明](https://docs.ollama.com/context-length)

「运行概览」中的速度和深度分别保存。速度选快速、均衡或耐心；深度选标准、深入或充分。速度不会自动降低深度，深度也不会改变速度。

在「职责路由」中可以单独给「人物计划复审」选模型。旧设置未添加这一项时，系统沿用「人物决策」的模型。标准和深入档复核一次，充分档复核两次，调用记录按「人物计划复审」计入用量和耗时。

发出一条实际 GM 查询或行动，可以核对连接是否能完成生成；「发现模型目录」本身不是生成测试。最近的调用记录位于「调用记录」，未知用量和费用会显示为未知。

## 游玩与 GM 模式

打开世界后，网页会载入当前分支的玩家视角和持久对话。在输入框上方选择模式：

- **自动**：由 GM 判断输入属于查询、角色交流还是行动。
- **问 GM**：询问当前角色可知的信息。
- **角色说话**：以角色身份进行世界内对话。
- **行动**：明确提交世界行动。
- **作者指令**：切换到作者输入通道。需要修订已返回的设定组件时，请在「设定档案」中使用预览和提交流程；此模式本身不绕过组件验证。

输入框按 Enter 发送，Shift+Enter 换行。查询与假设以服务端返回的时间影响为准；行动结果以服务端提交状态为准。若页面显示请求状态未确认，可使用「使用相同请求重试」，不要另发一条相同的行动。

「观察周围」直接读取当前角色可确认的人、地点与公开线索，世界时间保持原值。在场景或调查日志中选定线索，可直接建立私人案卷。也可以自行编辑想说的话。已送出的对话在刷新后可核对回执。失效的原话可以取回编辑。若还有待发对白或已提交对话等待处理，先回到对话区，再选择何时出发。

现代城到达调查目标指定地点后，只登记抵达阶段。可按场景提示继续找已知线索，具体结论在私人案卷中查看。人物卡上的公开作息说明通常安排，同场看到人物出现在不同地点时可当面询问缘由。

若页面提示人物回复格式无效且对话没有写入世界，输入框会恢复刚才发送的文字。你可以修改后重新发送。此前的模型调用可能产生费用，可在「模型与运行」查看。

如果提示「世界存档当前正忙」，稍后点「使用相同请求重试」。引擎先找原提交回执，已结算的行动会返回原结果。尚未提交的请求可能重新调用模型，用量会记入「模型与运行」。

在「设定档案」预览人物能力或地点路线时，编辑器会标出冲突字段。例如禁用魔法的背景会指出新增的法术能力，断开的路线会指出起点或目的地。看到提示时可在原草稿上修正并重新预览。

选中 NPC 后，在「性格与价值」可逐项锁定性格分值、特征或价值观。要修改已锁定的字段，请先取消勾选并提交解锁，再编辑原值。对话、经历和关系会照常记录，锁定值可在作者历史中回放。

如需保留某位 NPC 战败后的剧情，可在其「能力」编辑器开启「战斗保命」。致命战斗伤害会让该 NPC 倒下、失去行动能力并结束交战，伤势照常记录。在可治疗地点，同地且具备照护技能的角色可用自己的药品处理造成失能的伤口。寿终及其他伤害仍按世界规则结算。

已保存的 GM 回复可选择「简洁改写」或「文学改写」。改写通过模型生成并单独保存，可在该条回复中切回原文。事件、回执和人物记忆继续以原会话为准。同一条回复的同一风格首次成功后，之后直接读取保存的版本。

要销毁在场的实体证据，请写出它在场景中显示的完整名称，例如「请销毁『旧值班登记册』」。同名或指代不明时，GM 会要求澄清。

途中可能发生承诺到期、人物寿终或其他世界事件。使用持续行动面板的「开始旅程」，选择已知路线和足够的时长，旅程会按这些时点推进。旅途中可查看进度和已发生的事件，抵达或遭遇中断后再选择下一步。承诺截止时间仍按世界时钟结算。

新建的 2.0 世界在「调查日志」中提供可接触的开局案卷。点「建立案卷」会填入可修改的行动文字，发送后才建档。向在场居民询问历史说法，检视本地登记簿，或搜索并前往旧址查阅档案，再请 GM 核对观察与证词。将复核加入案卷后，可以写出私下判断或明确要求当面公开指认。结论依据已经归档的证据，公开误指认可能影响对方对你的信任。案卷和复核记录属于当前角色。已有世界继续使用创建时的开局内容。

若案卷已经排除你公开指认的人，可以在双方同场时用「行动」明确撤回，例如「我现在当着某人的面公开更正，撤回先前对他的指认」。调查日志会显示更正状态，证人下次交谈可记得这件事。案卷保留原结论和发生过的指认，对方仍可决定如何看待后续解释。

更正后，可在双方同场时用「行动」把你愿意说明的原话交给对方，例如「请把这段解释交给某人：『我当时没有先核对记录，我愿意听你把经过说完。』」。调查日志显示解释和回应。对方可以接受、拒绝或暂缓，由玩家控制的人物须由其玩家回应，托管 NPC 可受邀自行决定。

在「行动」模式可明确向在场的成年角色提出私人恋爱邀约。发出后可在「私人邀约」查看待回应和历史记录。受邀人的接受或拒绝、发起人的撤回，以及任一参与者的结束操作都会先填入可编辑草稿。只有发送并通过规则校验后才写入存档。

提出邀约时可以附上约会时间，写明起止两个世界秒数。两人都同意后才占用该时段。已有相交的约会时段、或约会开始时仍未同意，都会使接受失败。结束已接受的邀约时会释放未来时段。时段只对参与者显示，实际见面仍由之后的行动推进。

在开始时刻到结束之前，如果两人都在同一地点，可以选择「准备登记本人出席」并发送行动。每人只能登记自己一次。参与者可查看各自的出席时间，分支历史会保留已提交的登记。

在约定时段也可选择「请求对方决定赴约」，让世界托管的 NPC 自行决定登记或暂缓。双方须在同一地点；任一方有仍有效的在岗班次时，规则会拒绝登记。由其他玩家控制的角色须本人登记。

双方已登记且会面结束后，可以在「关系邀约」里选择更亲近、感受不变或感到不安，准备并发送记录私人感受的行动。每人可保存一次。玩家视角只显示当前角色自己的记录。

你也可以请托管 NPC 自行回顾会面。对方可暂缓，或私下保存自己的感受。以后交谈时，可以从他的回应和提出的边界了解想法。

要明确建立伴侣关系，在「伴侣关系」里选择可提议的在场成年人物并发送草稿。提议会进入待回应状态，接收方明确同意才会成立。你可以请求托管 NPC 自行回应，或由控制接收方的玩家决定。已成立的关系可由任一方结束，每对角色的记录独立保存。

可以在草稿中写明「私下交往条件」，例如双方可以和别人约会、暂时只让彼此知道。发送后用回执核对实际附上的原话。待回应期间，当前提出方可修改，接收方可提出反条件。填入本轮完整条件后再发送，双方看见新版和当前需回应的人。接受、拒绝和撤回均以当前版本为准。定向告知第三人只分享关系状态，交往条件仍留在两位参与者的记录中。

想把自己的一段已成立关系私下告诉第三人时，在「伴侣关系」的「定向告知」中选择关系和同场接收人，再把草稿填入行动输入框。也可以直接写「我只私下告诉某人，我和某某已经是伴侣」。发送成功后，接收人能在「收到的关系告知」查看自己当时听到的陈述。旁人不会获得这条记录。GM 回答时会区分所闻与当前可核实的关系状态。

世界所有者可以在发出的邀约旁选择「请求对方回应」，让仍在场的 NPC 按自己的价值观、熟悉程度和对发起人的印象决定。接受或拒绝会写入当前分支，暂缓则保留待回复。由其他玩家控制的角色须本人回应。

与同一位角色继续对话时，NPC 可以参考两人最近一次邀约在当前分支的状态。其他角色的对话没有这份记录。要改变邀约，请使用相应行动。

在「领导表决」中，在任者可为选举或议会制组织提名接任者。合资格成员可准备自己的投票草稿。单人游玩时，世界所有者可以请 NPC 独立投票，也可等对方作决定后再结算。弃权会记录一张票，暂缓会继续等待。面板显示自己的票向和最终结果。议会表决要求相应议席已配置 `authority.succession_vote` 投票授权。

同一面板的「领导席位提名」供有资格的选举成员或议会议员操作。选候选人后先确认输入框里的草稿，再发送。如果组织领袖空缺，而登记的领导职务都由同一位在任成员担任，可以发起表决确认此人是否成为组织领袖。开票后，发起者可请托管 NPC 自行投票，也可在结果已确定时结算。表决未通过时，组织领袖席位仍空缺，现有职务由原持有人继续担任。

世界作者可以在选举或议会制组织的治理组件中启用「空缺时由 NPC 按年复查并表决」。世界快进和角色长行动都能结算到期复查，合资格的 NPC 可以提名，也可以本年继续留空。开票后，NPC 独立投票，达到章程门槛才产生领袖。议会缺少登记选民时，或有投票权的角色由玩家控制时，成员仍可在条件具备后自行办理。行动恰在复查时点到达目的地时，先记录抵达，再完成同一时点的复查。

如果治理或选民名单在投票期间发生变化，旧提案会停止接受投票或结算。作者可在世界概览取消失效提案，历史选票仍保留。重新提名会按当前章程和成员资格建立新的名单。

「通行协定」会显示当前代表有权提出的登记路线。选定缔约势力和路线后，输入到期的绝对世界秒数，生成可编辑提案。世界所有者可请 NPC 代表独立回应。另一方批准后，该方向的通行和发运才可能解锁，其他路线、交通方式及目的地权限仍各自核验。拒绝和暂缓不会开放路线。到期或撤销会停止授权新发运，已经出发的货物继续按在途规则结算。

接收方代表还可以提出更早的到期秒数。NPC 独立回应时，也可以从规则提供的较短期限中还价。发起方收到期限反提案后可以接受或撤回。接受后按缩短的期限生效，待接受期间仍不能凭这份协定发运。

在 2.3 世界的「职业」面板中，选择本地岗位填入入职草稿并发送。入职后，「本人任职」会列出登记的工时和工资。角色到达登记工作地点后，选择「准备完成一班」，确认草稿并发送。完成时会推进世界时间、更新角色生活需求并发放工资。离职后仍可查看该段任职历史。

在「长行动」也可选择「按既有岗位排班工作」。选定任职、首班时刻、重复间隔与计划期限，可填写本人该岗位工资币种的余额目标。确认后，后台处理例行班次和可用补给，按正式工资规则逐班入账。达到目标或期限时完成，需要处理排班、岗位或自理问题时暂停。作业会列出已发薪班数、累计工资、最后发薪时间以及该次入账后的余额。购买物品需另行下达行动。

工作作业因需要自理而暂停时，可以先在对话里下达休息等行动，再选择「继续」。作业从已经保存的世界时间按原排班继续。处理期间错过的班次会显示为跳过，工资按随后实际完成的班次入账。

也可在对话的「行动」通道说清安排，例如「从明早九点开始，按我现在的岗位每天做一班，安排一个月，工资账户余额到 65 就结束」。引擎按 30 个世界日折算一个月，回执会列出首班、频率、期限和余额目标。用「问 GM」可以回顾已发几班工资、累计实收和最后一次发薪后的余额。

若自己的人物已在作者编辑的「每日作息」保存工作时段，也可以直接说「接下来一个月照常上班，攒够买四单位燃料的钱就告诉我」。引擎根据本人有效任职、工作地点和已保存的时段确定下一班。回执会列出首班和重复规律。排班不明确时，按 GM 的提示补上岗位或班次信息。

也可指定要攒钱买的商品和数量，例如「从明早九点开始每天一班，最多一个月，攒到买得起本地挂牌的四单位燃料就停」。在排班表单中可选「商品储蓄目标」，它和固定余额目标只能选一项。商品须在当前工作地点可见，并以该岗位工资币种挂牌。系统按已结算时点的报价和库存核对。买得起时完成，回执保存当时的报价、工资账户余额和确认时间。挂牌或所需数量无法购买时暂停。原挂牌恢复后可尝试继续同一作业，购买仍需另行下达行动。

在「推进世界」期间，托管 NPC 已有有效任职、身在工作地点且每日作息包含匹配班次时，会自动开始上班。有效出勤在班次结束时按雇主账户余额结算。在岗期间的约会登记会被拦截。

在「长行动」选择「旅行」和一条可达路线，再填写允许这个作业推进的时间。时窗要覆盖路线本身，并为出发前的自理留出时间。出发会记录在存档里，途中可以暂停作业。再次推进该旅途时，角色沿已登记路线继续，实际到达后才可在目的地行动。

选择「连续行程」可从当前地点开始，逐段添加已知且相接的路线。预览会分别列出计划纯路线移动时间、玩家授权时间窗口，以及两者相减且不低于零的路线外余量；余量可用于休息、粮水和途中停留，但不表示系统估算了这些事项所需时间。勾选自动自理后，角色可在途中休息并使用本人持有的有效粮水。若余量为零，自动休息或补给可能因窗口不足而无法完成，建议增加授权时间；只要窗口覆盖纯路线移动时间，零余量本身不会阻止计划提交。实际遭遇、无法取得所需资源或排程超出窗口时，作业会带着已提交进度暂停。完成后，「已抵达路段」显示实际到达情况，「已用时间窗口」显示耗时。

在「角色行动」中可选「日历年」和附加日历日，用本世界的年长和日长填写旅行、学习或工作等活动的授权窗口。例如一年为 360 日的世界中，填一年再加七日，会授权 367 个世界日。

遇险导致路段中断，或原时间窗口已经无法容纳剩余行程时，选择「前往新行程规划」，从角色当前实际位置选择路线和新的授权时间。此前已抵达路段仍可在旧任务记录里查看。可以补给后继续的暂时停留仍提供「继续」。

下一段道路关闭或路线资料变化时，面板会说明暂停原因。可以等待条件恢复，也可从当前位置提交一份替代行程，并保留原来的暂停任务及抵达记录。缺少通行许可时，取得许可后可在原授权期限内继续。遇险、补给不足和授权到期会分别提示处理办法。

在「行动」中也可以沿途明确说出已知地点的顺序、最多推进多久，和是否允许途中自理。作业排队回执列出实际登记的段数和窗口。「问 GM」可以按作业回顾已抵达的路段、角色可见的地点和实际抵达时间。查询期间世界时钟保持在当前提交。

例如，已知「驿站」与「边城」有相接路线时，可以说「先去驿站，再去边城，最多走一年。途中可以自行休息，用我现有的干粮和水。」普通赶路和授权内的自理会继续结算。途中可能已发生收成、价格变化或通行协定到期，等需要你处理补给、许可或改道时，再从作业记录查看停在何处、哪些路段已经走完。

同一路段的不同旅程可能一路平安，也可能在不同的日期遇险。作业会在实际发生险情的时刻停下。存档重开或工作器更换后，已经出发的路段沿用登记的时点。

世界作者可在「设定档案」的地点组件中添加「行程停留机会」，例如只在一段时间内开放的集市或能探查的旧址。也可设置行程至少已走多久才提示。角色实际抵达该中途地点，且机会在当时有效，行程才会停下来等你选择。「继续原行程」直接走下一段。「在此停留」会让角色留在已抵达的地点，你可以在对话中行动，再在原授权时限内继续同一行程。选择停留本身只记录停留，交易、应邀或调查都由玩家另行发起。世界备份会保存已确认的停留选择及抵达历史。导入世界备份后，可从角色保存的位置重新安排后续行程。

新建世界时可选「v2.8.0 · 途中机会」。现代、低魔封建和修仙各自带四个登记地点和可在当地查看的告示。部分机会只在开局指定日期内出现，部分要在已旅行数日后才会提示。想体验开局机会，可以规划经过起始地区、再到一个已知邻近聚落的连续行程。两种人口模式均支持这个版本。

只有一条本人的行程在等待这个选择时，也可以在「自动」或「行动」通道直接说「在此停留」或「不在这里停留，继续赶路」。回复会确认选择已提交，是否出发以作业进度为准。同一句话放在「问 GM」通道只会用于询问。你还可以问「当前停留机会是什么，我有哪些选项？」来了解已出现的机会。若有多条行程同时在等回复，请在对应行程上选择。

长行动面板按当前世界历显示已提交时刻、目标和预计抵达日期。提前完成时，「已用时间窗口」显示实际用时和原授权时长。具体世界秒仍可在相邻说明中核对。

在对话里明确要求动身时，若途中有必须分段结算的世界事件，引擎会安排旅行作业。满足通行条件并处理完当前时刻的世界事件后，作业按玩家要求出发。回执中的抵达时间是预计值，路况和生存压力仍可能让旅程暂停。

打开旧存档时，若当前分支仍有已故角色占用岗位，设定档案的「世界概览」会显示「历史岗位空缺」。世界所有者或编辑可选择「结束已故任职记录」。补结算记录在当前世界时点，保留原入职来源和已故角色的历史。

在时间推进面板可选择「角色行动」或「全世界快进」。角色行动提供等待、休息和符合条件的旅行。若当前角色已有登记技能，可选择「学习」，再选技能和时长。作业会分段推进世界时钟，按规则扣除休息、自理与中断占去的时间，实际练习才增加该技能和人物经验。可在任务状态允许时暂停、继续或取消。

存储空间不足时，长行动会保留最近一次已提交的进度。若面板显示「存储空间不足」并已暂停，恢复空间后点击「继续」即可从原作业接着走。若存档来不及写入暂停状态，本地服务会在原租约失效后重新领取该作业。可从进度面板查看最后已提交的时间。

用「询问 GM」可核对本人最近六段已结算练习的技能和起止时间，包括长学习作业内的片段。等待和自理期间的时钟进度不会记成练习。

也可以问一项学习作业目前为何暂停、原定多久、实际练了多久。GM 按作业记录确认状态和截止时刻，再按同一作业汇总已提交的练习和片段数。能查到的旧作业可能只有练习记录。若恢复的归档只保留了事件历史，GM 仍可回读练习片段。

学习因匮乏暂停后，可以先饮水、进食或休息，再继续原作业。补给推进的时间会占用原计划时段。恢复时仍核对同一角色、同一技能和原定截止时刻。超过截止时刻后，需要重新安排学习。

也可以在对话里明确开始一项有时长的学习，例如「我现在闭关练自己的修炼功法两年」。引擎按当前世界日历计算时长并排入作业，任务会出现在时间推进面板。若只是问「闭关两年可能发生什么」，GM 会回答，世界时钟和任务列表都不会因这条问题改变。修炼境界仍由单独的突破行动结算。

如果想在安全值达到特定数值时停下，可以填写面板中的「安全暂停阈值」，也可以在开始请求中写「安全值不高于 40 时暂停」。数值范围为 0 至 100。作业记录会显示选择的阈值。已满足时立即暂停，处理完原因再选择「继续」。

全世界快进由世界所有者提交，玩家角色也和其他人物一起经历需求消耗、衰老和死亡，提交前需要确认。按面板提供的时间单位填写时长。世界快进支持按当前世界日历输入至多 600 个日历年，可加不足一年的日数，提交前会显示目标 tick。开始后，页面显示后端已提交的世界时钟、目标和进度。遇到玩家有权处理的继任，页面会列出服务器返回的选项。若出现规则边界或逾期计划事件，页面会显示中断原因。

新建的全世界快进会记录当时的深度档。标准、深入、充分分别允许常规模拟窗口最多推进 30、14、7 个世界日。到期事件、寿终和资源短缺仍可提前截断窗口。后台自动接续这些窗口，玩家只需在需要本人决定时介入。这个上限用于全世界快进，角色的排班、旅行及修习仍按各自计划推进。

在「行动」中可以明确说要向哪个可达的固定收货点发运哪种自有资源、发运多少。发送后货物进入在途保管，目的地按路线耗时收货。展开「货运状态」可查看当前角色参与的运单和到达时点。如果角色是指定收货人且到达时不在场，货物会暂扣。回到收货地点后点「准备领取」，检查填写的行动文字并发送，确认交付后货物才进你的库存。

当你是当地政治体的现任领导、与领取人一同位于有到货粮食的仓库时，展开「发放到货粮食」选择货运和领取人，输入数量后检查并发送草稿。发放完成后，粮食进入领取人的库存，后台自理可按需要消耗。

向在场人物立下归还承诺时，在「行动」中说明物资、数量和截止时间。「我的承诺」显示角色作出的承诺，以及别人对角色作出的承诺。「准备履行」和「准备解除」会填入可编辑的行动文字。发送后，履行会转移约定的实际库存，解除只能由受诺人确认。错过截止时间，快进到下一秒时会结算逾期。选择「问 GM」可以只回顾承诺，当时的时钟和库存不变。

要当面赠送物资，可以在「行动」中说「我提议送给 Yara 两份我自己的谷物。」提议仅双方可见，默认在七个世界日后到期。收礼人可在双方仍同地时接受，接受后按实际库存交接。送礼人也可以撤回。网页「私人赠与」中的回应按钮会填入草稿，发送后才执行。世界所有者在扮演送礼人时可以请无人控制的 NPC 自行回应。选择「问 GM」可以核对自己参与的赠与及实收数量。

使用启了承诺信任策略的世界时，你可以对自己的逾期承诺选择「准备补还」。草稿发送后，需本人和受诺人在场，且可用库存足以一次交清。补还后面板显示「已逾期 · 已补还」，原逾期仍可在记录中查阅。每条承诺可补还一次。

「市场挂牌」列出当前角色在当地可见的价格、币种和最低购买量。点击「问 GM」会填入可编辑的问价草稿，发送后也不会提交交易或推进时钟。挂牌价使用该币种的最小单位。例如挂牌 4 表示每单位物资标价 4 个最小货币单位。实际购买时，交易规则会重新检查库存、价格、最低量与余额。

有预算上限时，可以说「现在买两份燃料，只有总价不超过六个信用点才成交」。GM 按这次请求提交时的挂牌价核对整笔金额。若超出上限，本次交易结束，余额、库存和世界时间保持原值。你也可以先问「如果把上限设为五个信用点，按当前报价能成交吗？」来讨论这一条件。

### 机构借款与还款

角色持有有效的机构代表或财库权限时，可以从聊天发出借款方案。比如在开局说「提出借款方案给青石织坊。本金 40 个信用点，应还总额 44 个信用点，接受截止第 30 秒，到期第 120 秒。」对方确认接受时，规则按双方财库和当前资金核对本金划拨。借款期限用当前世界的时钟，回执会列出已登记的条款。

借方可以先向 GM 查询已有条款，再说「确认接受这笔借款」或「请偿还 12 个信用点」。有多笔可处理的借款时，请选明回执中的借款编号。跨过到期时刻后，未结清部分会登记为逾期。随后可以继续还款，已发生的逾期仍会保留在历史里。

持有签署权时，游玩页的「机构借款」会列出授权范围内的条款和应还余额，并把逾期、待还与仍可接受的方案放在前面。用「问 GM」核对条款，或准备提案、接受、拒绝、撤回和指定金额的还款。按钮将文字填入输入框，发送后才交给 GM 与规则引擎处理。附有额外条件的借款指令需要先明确条款再提交。

在「机构借款 → 财务核对」里可看到已到期借款、财库缺口和另处同币种储备。需要动用时，输入要从自有储备调入财库的整数金额，选择「准备调入财库」，核对草稿后发送。入账后可以另行准备还款，原有逾期记录仍可查询。

## 制作和播放本机语音

在 Windows 上以 `--windows-speech` 启动本地服务可启用系统语音。若要指定声音，可加 `--windows-speech-voice "已安装声音的名称"`。

在「历史与分支」中选择支持语音的本分支事件，打开「为此事件制作媒体」，选择允许的可见范围，填写希望朗读的文字，再提交媒体任务。完成后可使用事件下方的播放器。刷新页面或重开本地实例后，仍可从原分支查看该事件的任务和音频。语音生成使用本机 Windows 声音，不消耗 GM 模型 token。

媒体任务状态读取遇到暂时断线时会按递增间隔最多自动重试四次；权限撤销、任务不可访问等终态会停止轮询。自动重试停止后可手动重试读取状态。

## 浏览与编辑作者设定

打开「设定档案」，页面会显式标示「作者视角 · 剧透」。顶部范围切换为：

- **世界概览**：查看分支、时间、历法、状态以及作者投影统计。
- **人物**：浏览作者投影中的人物；选择人物可查看返回的公开资料和类型化组件。
- **地点**：浏览当前作者投影实际返回的地点。
- **势力与组织**：浏览实际返回的政治实体、组织、派系、公司或政府。

列表和组件详情以当前分支的作者投影为准。地点或组织列表为空时，表示服务端没有返回相应实体；此页面目前不提供新建地点、国家或组织的表单。

对已返回且已注册的组件，可在「组件修订」中选择组件，编辑内容并填写修订原因，再选择「验证并预览」。检查服务器返回的前后差异和版本信息，确认后才会提交。提交失败或版本过期时，按页面提示重新读取作者投影，再生成新的预览。

地点和治理组件提供常用字段表单与高级 JSON。表单可从当前作者投影选择区域、上级地点、成员、领导者和职务任职者；修改这些字段时，其余组件字段会保留。服务器会校验组件结构、字段取值以及完整世界中的地点、成员和路线引用；无效的组件或跨引用会被拒绝。高级 JSON 可改变整个组件，不是只提交单个字段，编辑时请保留未改动字段。

### 创建人物

在「设定档案」→「人物」选择「新增人物」。当前作者投影必须包含至少一个地点。填写名称、地点、公开身份、公开描述、价值观、性格特征，以及可选的作者秘密和角色目标；先生成服务器预览，核对全部字段后，再选择「确认创建人物」。只有服务端提交成功后人物才会出现在列表中。秘密和目标属于作者资料。

填写角色目标后，可以选择与出发地不同的「目标目的地」。预览会列出选定地点。系统为这个人物授予普通旅行能力，并在自主计划实际到达该地点后结算目标。人物仍需发现可走路线并遵守当地限制。若希望引擎主动安排计划，请在创建时填写至少一次自主目标复审，随后按正常方式推进世界。

已存在的托管 NPC 可在「安排自主目标复审」中沿用现有目标，或选择新的目标目的地并填写目标描述。确认预览后，私有目标和复审安排一并生效。NPC 仍使用他已有的能力和路线权限。

导入角色卡时，先选「所在地点」，再在「从角色卡导入」选择 V1、V2 或 V3 的 JSON 或带标准角色卡元数据的 PNG。JSON 上限为 256 KiB，PNG 文件上限为 8 MiB。同一张 PNG 同时保存 V2 和 V3 时采用 V3。核对服务端预览的名称、公开描述、性格和未导入字段。可返回修改已映射的草稿，也可确认创建人物。

确认后，原始角色卡 JSON 随作者历史和世界备份保存。PNG 导入保留选中的角色卡文字数据。作者预览列出尚未映射的字段，包括扩展和嵌入的世界书。角色生效字段以预览为准。

独立世界书在「设定档案 → 世界概览 → 世界书」导入。选择 UTF-8 JSON 文件，填写导入批次名称，生成预览后核对正文、关键词和未导入原因。可导入的条目默认仅作者可见。勾选允许进入玩家 GM 上下文的条目，再确认导入。公开条目会在字面关键词命中或标记为常驻时成为 GM 可引用的背景。存档中的权限、角色位置和实际结算以世界记录为准。原始文件随作者备份保存。

人物组件修订只处理作者档案已返回且有注册编辑器的组件。

### 试演人物

在「设定档案 → 人物」选一名活跃 NPC，展开「人物试演」。选择利诱、资源威胁、亲友冲突、证据反驳、补给短缺或失联，再点击「开始试演」。模型连接在「模型与运行」中按「作者辅助」职责配置，调用计入模型后台。

报告显示人物的选择、对白、模型给出的动机、待核对条件和引用的本人资料。模型先生成供作者阅读的决定和动机，再按公开资料生成面向假设中对话者的对白，因此一次试演包含两次调用。状态版本和世界时刻标记了试演使用的快照。试演结论保留为当前页面的报告，世界时钟保持原值。

## 历史、分支与备份

在「历史与分支」选定分支后，选择「下载玩家报告」可保存当前角色的 JSON 视图，包括此刻可见的世界资料和个人已知信息。「下载世界备份」用于保存及恢复完整世界，按作者权限开放。

在「世界库 → 导入世界包」选择 ZIP，先预览版本要求、依赖和无法启用的字段，再确认导入为新世界。原 ZIP 中的扩展字段和图片音频会随源文件保存。导入后的世界在「历史与分支」提供「下载源世界包（含作者资料）」，完整备份也会保存此源文件。分享给玩家前，可改用当前角色的玩家报告。

已导入的世界可在「历史与分支 → 更新世界模板」上传同一包的新版 ZIP，查看会应用哪些字段、哪些字段已单独修改，以及分支起点。确认后，成功的更新会出现在新分支，原分支可继续游玩。预览显示冲突时，可先核对模板与当前人物设定。旧格式备份可恢复为独立副本，再在副本中下载 2.0 分段备份。恢复默认沿用原规则；如预览中列出可用的规则升级，可阅读影响后为副本选择新版。源存档继续使用原规则。

打开「历史与分支」：

- 从顶部选择分支查看该时间线的事件记录；事件载荷可展开查看。
- 在完整可分叉事件旁选择「从此处分支」，或在分支面板选择「从当前末端创建分支」。输入名称并确认后会切换到新分支；源分支和历史保留。
- 选择「下载世界备份」保存归档。需要恢复时，选择「验证备份归档」，等服务器校验并回放完成后，再选择「恢复为独立副本」。恢复会建立新数据目录，不覆盖源世界。
- 压缩归档默认上限为 128 MiB，展开后为 512 MiB。长历史归档超过上限时，可在启动运行时添加 `--backup-compressed-mib` 和 `--backup-expanded-mib` 并指定所需的 MiB 数。导出和导入时均使用运行中的服务配置。容量探针 `scripts/probe-world-advance.py` 也接受这两个选项，用于最终导出测量，同一长跑可沿用原世界和作业标识。
- 恢复成功后，使用页面给出的复制按钮。在仓库根目录的 PowerShell 中运行完整命令，再访问页面给出的本地地址。启动器只在新 Python 子进程中清空 `WORLD_ENGINE_DATABASE_URL`，保留当前终端的原环境；若 8001 被占用，可在页面改用其他空闲端口，命令和地址会同步更新。新副本不会自动启动，保持原来的 8000 端口实例和恢复副本端口实例分开使用。

## 自主社会模拟

幻想乡 1.6.0 在同一世界时钟中处理住处、值守、出行、交谈与临时事务。向 GM 查询和使用场景观察保持当前时刻。用「行动进度」提交等候或长休息时，回复中的进度对应已提交的世界时间。任务进行中仍可查看场景或问 GM。明确写入的请求遇到占用时会保留原话，并提供行动进度入口。连接意外中断后，页面会先核对上一条请求的回执。

同地且有实际联系的人物可能打招呼、交流或各自忙碌。组织按章程、人手、资源和在场成员处理事务。地区和组织的暗骰命中后，人物决策模型可提出临时邀请、请托、观察或流言。组织中当前有权的成员还可以提出待研究的内部议题。场景卡展示当前位置仍然有效的公开观察；其他信息通过当事人、可见线索和有权访问的历史记录获得。

好感、信任与熟悉度各有方向。连续做等价的小事时，分数变化会逐步减弱。分数绝对值达到 60 后，例行变化幅度缩小。进入绝对值 80，或从这一档向任一方向变化，需要经过规则确认的关键证据。提出邀约、解释和礼物时，对方的回应及实质后果由相应的行动流程裁定。

在仓库根目录构建幻想乡 1.6.0，再到「世界库 → 导入世界包」选择生成的 ZIP 和介入点。

```powershell
.\.runtime\venv313\Scripts\python.exe -B scripts/build-gensokyo-reference.py --social-world
```

作者可通过 `--ambient-settings <JSON路径>` 为本次建包指定人间之里 `human-village`、魔法之森 `forest`、博丽神社 `shrine`、红魔馆 `scarlet-household` 或守矢势力 `moriya-faith` 的频次。以下设置每两世界日检查人间之里，命中几率为 30%，冷却为三世界日，允许最多两个同时有效的事件。命中几率以万分点填写。设为 `0` 时仍会记录检查，但始终不触发该范围的新事件。

```json
{
  "human-village": {
    "check_every_days": 2,
    "chance_basis_points": 3000,
    "cooldown_days": 3,
    "concurrent_limit": 2
  }
}
```

更改配置后重新构建，并将生成的 ZIP 导入为独立世界。已有存档继续使用原本登记的规则和历史。`--playable-world` 可构建原来的幻想乡 1.5.0。

现代都市、低魔封建、长生修行可在新建世界时选用 2.14.0 的自主社会开局。接触与组织机会依据该背景已有的地点、人物和职务关系建立。

## 当前界面边界

- 设定档案支持新增地点、国家和其他组织，先预览定义与附属账户，再确认创建。路线只能引用已存在的目的地，有限采集需明确配额与接收账户；新金库初始余额为零。版本冲突后需刷新并重新预览。完整世界创建向导、规则配置流程和整体影响报告仍未接入。
- 长期容量以现有存档的连续审计区间为准，报告包含全程人口低点和机构运转记录。[容量验收](acceptance-matrix.md)
- 媒体由历史事件触发。Windows 语音插件可在匹配事件上生成并播放 WAV，其他媒体需要已安装且匹配该事件的插件。[制作和播放本机语音](#制作和播放本机语音)
- 当前显示本地身份；没有成员邀请、角色分配、角色切换或多人大厅。模型职责路由中的“角色”指 GM、人物决策等模型任务类别，不是用户权限角色。

在「模型与运行」的调用记录中，可查看失败发生在连接、读取、写入或协议等哪个阶段，并导出 CSV。阶段和可能计费按具体尝试显示，旧调用无法判断时显示未知；曾经有一次连接失败不代表整次调用没有费用。

需要本地模型时，在项目根目录的 PowerShell 中运行 `.\scripts\local-ollama.ps1 -Status` 检查现有服务。去掉 `-Status` 可启动或复用原目录模型与已有权重。若上次异常退出留下管理记录，脚本在确认原进程已退出、端口空闲后归档记录并继续启动。输出的 `archived_owner_record` 指向归档位置。`-Stop` 只会停止本脚本能验证所有权的进程，复用的已有服务保持运行。已验证能发现 8B 与 14B 模型，8B 已通过一次结构化 GM 假设问答。

## 与同一位人物再次预约

已同意的限时邀约在时段结束后保留为历史，可向同一个人发出新的邀约。未答复的限时邀约在原定开始时刻失效。新邀约需要对方重新答复。在行动输入中写明对方姓名和起止世界秒。

## 原角色死亡后续玩

在游玩页使用「继续当前分支」，从当前分支选择仍活跃、可由你控制的人物。确认后用新人物的视角开始新的对话。也可以先从历史建立分支，再在分支中接续。在选择之前，仍可向主持人提问。

## 遭遇中停战

交战时打开「交战停战」可准备提议，或在收到提议时准备接受或拒绝。按钮只把文字放入输入框，由你确认发送。房主发出提议后，可以请未受玩家控制的对方自行答复。对方明确接受才会结束这次交战。之前的伤势仍需处理。
